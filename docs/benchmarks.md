# Benchmarks

Raw numbers behind the throughput race on the [home page](index.md#performance), generated by
[`perf.py`](https://github.com/RogerThomas/lothc/blob/main/perf.py) on an AWS `c8a.xlarge` (AMD
EPYC, Python 3.14) against the bundled Rust/axum JSON server, the server and client pinned to
separate cores: 50,000 requests at concurrency 100, after a 1,000-request warm-up (untimed).

`lothc`, `lothc-msgspec`, and `lothc-pydantic` are the same `HTTPClient` on its pyreqwest
transport (`native="off"`), differing only in `into`: a plain `dict` (unvalidated), a nested
msgspec `Struct`, or a nested pydantic `BaseModel`, each decoding the server's full response. The
`lothc-native` rows are the same three with `native="on"`. Every other library returns a `dict`.

|---|---:|---:|---:|---:|---:|---:|
| httpx | 1,004 | 1.0 | 996.2 | 73.21 | 421.79 | 8.52 |
| niquests | 3,155 | 3.1 | 317.0 | 30.56 | 70.99 | 10.90 |
| httpx2 | 3,247 | 3.2 | 308.0 | 30.75 | 31.01 | 3.59 |
| aiosonic | 13,783 | 13.7 | 72.6 | 5.58 | 13.90 | 2.74 |
| aiohttp | 21,653 | 21.6 | 46.2 | 3.44 | 8.12 | 2.54 |
| lothc-pydantic | 38,066 | 37.9 | 26.2 | 2.68 | 3.74 | 1.96 |
| lothc | 41,195 | 41.0 | 24.2 | 2.60 | 3.22 | 1.97 |
| lothc-msgspec | 41,528 | 41.4 | 24.0 | 2.41 | 2.73 | 1.96 |
| pyreqwest | 43,370 | 43.2 | 23.0 | 2.28 | 2.56 | 1.76 |
| lothc-native-pydantic | 56,738\* | 56.5 | 20.2 | 1.70 | 3.57 | 2.44 |
| lothc-native | 71,356\* | 71.1 | 15.4 | 1.53 | 2.27 | 2.18 |
| lothc-native-msgspec | 97,501\* | 97.1 | 11.2 | 1.11 | 1.80 | 1.97 |

\* The PGO-optimised build that the published wheels ship, measured in a second run on the same
machine, whose `pyreqwest` and `lothc-msgspec` controls matched this one within about 3%; within
that run, PGO was about 5% faster than the plain build. The row's other columns are from this
run's plain (non-PGO) build, which measured 88,778 / 64,760 / 49,745 req/s.

Sorted slowest to fastest (`x` = throughput relative to the slowest library, `httpx`, in this run).

## Worth calling out

`lothc-native-msgspec` does 2.2x bare `pyreqwest`'s throughput at half its CPU per request, while
returning a validated `Struct`. On pyreqwest, `lothc-msgspec` matches the unvalidated `lothc` row.
Re-run it from a checkout with `task perf` (see [Development](development.md)).

## Sync sequential

One request at a time on each library's blocking sync client, no event loop. `aiohttp` and
`aiosonic` have no sync client; `requests` has no async client, so it appears only here.

50,000 sequential requests (plus a 1,000-request warm-up, untimed) on the same machine and
server, plain (non-PGO) build:

| Library | Throughput (req/s) | Relative (x) | CPU per request (µs) | P50 (ms) | P99 (ms) | Peak Py Mem (MB) |
|---|---:|---:|---:|---:|---:|---:|
| requests | 2,476 | 1.0 | 403.6 | 0.40 | 0.45 | 2.21 |
| niquests | 3,140 | 1.3 | 317.8 | 0.31 | 0.58 | 2.47 |
| httpx | 4,009 | 1.6 | 249.4 | 0.24 | 0.50 | 2.01 |
| httpx2 | 4,437 | 1.8 | 225.4 | 0.23 | 0.24 | 1.64 |
| lothc-pydantic | 32,879 | 13.3 | 22.2 | 0.03 | 0.03 | 1.57 |
| lothc | 33,701 | 13.6 | 21.6 | 0.03 | 0.03 | 1.57 |
| lothc-msgspec | 38,893 | 15.7 | 17.8 | 0.03 | 0.03 | 1.57 |
| pyreqwest | 39,709 | 16.0 | 17.2 | 0.03 | 0.03 | 1.57 |
| lothc-native-pydantic | 46,149 | 18.6 | 13.4 | 0.02 | 0.02 | 1.57 |
| lothc-native | 47,456 | 19.2 | 12.8 | 0.02 | 0.02 | 1.57 |
| lothc-native-msgspec | 56,720 | 22.9 | 9.4 | 0.02 | 0.02 | 1.57 |

![Sync-sequential HTTP client throughput race — pyreqwest and lothc finish first, requests and niquests take much longer](assets/perf-race-sync.svg){: .perf-race-img }

Without pooled concurrency to hide it, per-request Python overhead dominates far more starkly:
every lothc and `pyreqwest` row is 7-23x faster than `httpx`/`httpx2`/`niquests`/`requests`,
none of which have a Rust transport underneath them, and `lothc-native-msgspec` leads again at
1.4x bare `pyreqwest`.

Re-run it with `task perf-single-call-sync`.

# `max_retry_after` stops retrying instead of clamping

Date: 2026.09.23

Status: Accepted

## Context

A server's `Retry-After: 3600` used to sleep an hour inside `get()`.

## Decision

Past `max_retry_after` (default 60s), stop retrying and raise the 429/503, so the caller can schedule its own retry from the header.

## Consequences

An early retry against a server asking for a long wait, usually rejected again, never happens.
